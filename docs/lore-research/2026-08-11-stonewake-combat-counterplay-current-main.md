# Stonewake Shield combat-counterplay evidence — 2026-08-11

## Scope

This current-main integration executes the already-authored `shadowslave:memory/stonewake_shield` / `shadowslave:memory_enchantment/settle` hook as one player-side answer to committed horizontal displacement. It does not add a Memory, enchantment, universal guard/parry/dodge system, damage formula, progression rule, reward rule, or Nightmare rule.

## Primary material rechecked

- Chapter 74, **Midnight Shard**: Memories have distinct Rank/Tier/Type identity and individual supernatural qualities; higher tier does not reduce them to one simple power scale.
- Chapter 694, **Key Piece**: Memories share summon/dismiss, self-repair-while-dismissed, and soul-connection traits while individual enchantments remain distinct functionality.
- Chapter 261, **Moonlight Shard**: a shield Memory can possess a highly specific supernatural defensive/physical property rather than merely being ordinary armour with larger numeric defence.

Official WebNovel publication was used to cross-check all three chapter identities. No checked primary passage establishes Stonewake Shield, `settle`, crouch-bracing, the force threshold, the damping multiplier, or its cooldown.

## Classification

- **CANON:** Memories are soul-associated supernatural objects with differentiated identities/enchantments; shield Memories can carry distinct supernatural physical properties; summon/dismiss is a general Memory trait.
- **INFERRED:** an already-authored defensive Memory enchantment can consume server-authoritative physical motion as execution input while Java-owned Memory identity remains supernatural authority.
- **DESIGN:** Stonewake Shield itself; `settle`; crouching as the brace gesture; at least 0.08 horizontal motion; reducing current horizontal velocity to 25%; preserving vertical velocity; 40-tick cooldown; player-facing wording; temporary iron-ingot item pixels.
- **UNKNOWN:** canonical Stonewake existence; passive-vs-active bracing; facing requirements; whether it should interact with damage, knockback resistance, stability, essence, terrain, specific creature powers, death/cross-realm state, or the authored `wake` enchantment.
- **COMPATIBILITY:** `MemoryOwnershipData` / `MemoryContentCatalog` remain Java authority. Minecraft velocity, crouching, item use, cooldown, model and chat are replaceable execution/presentation only.

## Combat-dance boundary

This slice is intentionally not a universal dodge or invulnerability button. The player must already be moving from a meaningful horizontal shove, must actively crouch/use the owned manifested Memory, and receives only reduced horizontal displacement. Vertical motion is not cancelled and damage is not negated.

That makes `settle` a possible response to displacement-oriented committed attacks such as the project Chainback pull without hard-coding Chainback identity into the Memory. Other movement, positioning, phasing, hardening, teleportation, or Aspect responses remain separate design capabilities.

The separate authored `wake` enchantment remains definition-only.
